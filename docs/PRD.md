# Teletype Memo — Product Requirements Document

## エレベーターピッチ

**Teletype Memo**は、作業中の思考をその場で捕まえる、追記専用のAI付きメモ受信箱である。MVPではターミナルから入力し、将来はデスクトップのグローバルショートカットから、どのアプリで作業中でも呼び出せるようにする。

作業中に浮かんだ疑問やアイデアを、タイトルや保存先を決めずにすぐ記録できる。後から「今日一日分のメモをまとめて」のように自然言語で依頼すると、AIエージェントが必要なメモを自律的に探し、Notion向けのページへ整理する。ユーザーがプレビューを確認して承認した場合だけ、Notionへ保存する。

Notionや一般的なメモアプリが「整理された情報を書く場所」であるのに対し、本アプリは**整理前の断片を最速で捕まえ、必要なときにAIが知識へまとめること**に特化する。

## 提供価値

- 作業画面を離れず、複数行の思考をすぐ記録できる
- 入力時にタイトル、タグ、保存先を決めなくてよい
- 「今日」「今週」「このテーマ」のような自然言語でメモを横断できる
- AIがメモを探すため、ユーザーがIDや検索語を覚えなくてよい
- 雑なメモをNotionへ載せられる形にまとめられる
- 外部への書き込みはプレビュー承認後にのみ実行される
- 過去のメモを編集せず、理解・訂正・判断が変化した過程を残せる
- 将来はターミナル外で作業中でも、グローバルショートカットから記録できる

## 既存ツールとの違い

| 比較対象 | 主な用途 | Teletype Memoとの違い |
| --- | --- | --- |
| Notion | 整理・共有された情報の蓄積 | Notionを開く前の断片入力と、Notionへ整理するまでの橋渡しに特化する |
| 一般的なメモアプリ | 手動での記録と検索 | AIが複数メモを自律的に調査し、依頼に応じて成果物を作る |
| テキストファイル | 高速で単純な記録 | 検索可能な形で蓄積し、後からAIとNotionへ接続する |
| AIチャット | その場での対話と回答 | ローカルに蓄積した自分のメモを継続的な情報源として使う |

## プロダクト原則

1. **入力を止めない**：メモ保存時にAIやネットワークを待たせない。
2. **整理を求めない**：タイトル、タグ、保存先を入力時の必須項目にしない。
3. **ローカルファースト**：元メモは端末内のSQLiteへ保存する。
4. **自然言語を主導線にする**：AI利用時にIDや細かなコマンドを要求しない。
5. **人間が最終決定する**：Notionへの書き込みはプレビュー承認後に実行する。
6. **処理を説明できる**：AIが参照したメモIDを確認できるようにする。
7. **原文を上書きしない**：ローカルメモは追記専用とし、訂正や補足も新しいメモとして残す。
8. **入力UIとCoreを分ける**：CLIと将来のデスクトップUIが、同じ保存・AI・MCP機能を利用できる構造にする。

## 対象ユーザー

- ターミナルを日常的に使うソフトウェア開発者
- 作業を中断せず、疑問やアイデアを残したい人
- 雑なローカルメモと、整理されたNotionの間を自動化したい人
- AIエージェントのTool、ループ、承認、外部連携を実装して学びたい人
- ターミナル外の作業中にも、思考を中断せず記録したい人

## 将来のデスクトップ体験

最終的な入力体験は、常駐するデスクトップアプリからグローバルショートカットで小さな入力ウィンドウを開く形を目指す。

```text
どのアプリで作業中でもショートカット
  ↓
小さな入力ウィンドウを表示
  ↓
タイトルや保存先を決めずに入力
  ↓
即座にローカルへ追記して閉じる
```

- 通常の画面には既存メモの編集機能を置かない
- 修正したい場合は「さっきのメモの訂正：...」のように新しいメモを追加する
- 保存時にはAI処理やネットワーク通信を行わない
- AIは追記された原文を読み、Markdown、日報、Notionページなどの派生成果物を作る
- 派生成果物は再生成できるが、元メモはAI処理によって変更しない
- データ消去はプライバシーや事故対応のための管理操作として分離し、日常の編集機能にはしない

現在のCLIは廃止せず、最初の入力フロントエンド、開発・デバッグ手段、自動化インターフェースとして残す。

## MVPの中心体験

### 1. 雑に記録する

```text
$ memo

New memo — submit with an empty line, cancel with Ctrl-C

> ツール実行結果もコンテキスト圧縮の対象になる？
> 長い出力を使って試したい
>

Saved memo #42
```

一行入力も利用できる。

```bash
memo "あとでコンテキスト圧縮を試す"
```

### 2. 自然言語で依頼する

```bash
memo ask "今日一日分のメモを学習日記としてまとめて"
```

ほかの依頼例：

```bash
memo ask "今週考えていたAIエージェントの論点を整理して"
memo ask "未完了のTODOを抽出して"
memo ask "コンテキスト圧縮に関するメモをNotion向けにまとめて"
```

### 3. AIエージェントが調査する

```text
依頼を解釈
  ↓
期間やテーマに合うメモを列挙
  ↓
必要なメモの全文を読む
  ↓
不足していれば別の検索語で再検索
  ↓
Notionページ案を作る
```

エージェントは参照したメモIDを最終結果に含める。

### 4. プレビューして承認する

```text
Title: 2026-08-29 学習日記

## 今日考えたこと
...

## 次に試すこと
- 長いツール出力でコンテキスト圧縮を確認する

Sources: #38, #40, #42

[y] Create in Notion  [r] Revise  [n] Cancel
>
```

`n`または空EnterではNotionへ何も書き込まない。`r`では修正指示を入力して再プレビューする。`y`の場合のみページを作成し、作成されたページのURLを表示する。

## コマンド仕様

### MVP

| コマンド | 動作 |
| --- | --- |
| `memo` | 複数行メモを保存する |
| `memo "text"` | 一行メモを保存する |
| `memo ask "instruction"` | 自然言語の依頼をAIエージェントへ渡す |
| `memo list` | 最近のメモを表示する |
| `memo show` | 最近のメモをキー操作で選択して表示する |
| `memo show <id>` | IDを指定して表示する |
| `memo search <query>` | 本文をローカル検索する |
| `memo notion connect` | ブラウザでNotion MCPのOAuth認証を行う |
| `memo notion status` | 接続中のNotionワークスペースを確認する |
| `memo --help` | ヘルプを表示する |
| `memo --version` | バージョンを表示する |

`list`、`show`、`search`は手動確認とデバッグにも使えるが、AI利用時の主要導線は`ask`とする。

### MVP後

| コマンド | 動作 |
| --- | --- |
| `memo export` | MarkdownまたはJSONへ出力する |
| `memo config` | モデルやNotionの設定を管理する |
| `memo purge --all` | 明示確認後に全ローカルデータを消去する管理操作 |

## AIエージェント

### Tools

MVPでは読み取りToolsを中心にする。

| Tool | 用途 |
| --- | --- |
| `listMemos` | 日付範囲や件数を指定して候補メモを列挙する |
| `searchMemos` | キーワードでメモを検索する |
| `readMemo` | 指定したメモの全文を読む |

Notion MCPが提供するToolは接続時に動的に取得する。ただし、Notionへの作成Toolはエージェントが会話途中で自由に呼べるToolにはしない。エージェントがNotionページ案を最終出力し、CLIがユーザーの承認を得た後にMCPクライアントから`notion-create-pages`を呼び出す。

### エージェント機能

- MVPではGemini APIの`gemini-3.6-flash`を使用する
- LLMが必要なToolと引数を選択する
- Tool結果を会話履歴へ戻し、複数ステップで調査する
- 最大ステップ数を設け、無限ループを防ぐ
- 現在日時とタイムゾーンをコンテキストとして渡す
- 最終出力をタイトル、本文、参照メモIDの構造として検証する
- ToolやLLMの失敗時も元メモを変更しない
- 詳細モードではTool呼び出し履歴を確認できる

## データ

### ローカルメモ

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | integer | ローカルで一意のID |
| `body` | text | 改行を保持した原文 |
| `createdAt` | datetime | 作成日時 |
| `updatedAt` | datetime | 更新日時 |
| `status` | text | 将来の整理状態に使用する |

元メモは追記専用とし、AI処理やNotion作成によって上書きしない。訂正、補足、撤回も新しいメモとして保存する。

### Raw Logと派生成果物

| 層 | 内容 | 更新方針 |
| --- | --- | --- |
| Raw Log | ユーザーが入力したローカルメモ | 追記専用。通常操作では編集しない |
| Derived Documents | AIが作るMarkdown、要約、Notionページ | 元メモから何度でも生成・修正できる |

Raw Logを原本とし、派生成果物は特定時点のメモを整理したビューとして扱う。

### 保存方式

- Bun組み込みの`bun:sqlite`を使用する
- macOSの既定保存先は`~/Library/Application Support/terminal-ai-memo/memos.db`
- `TERMINAL_AI_MEMO_DB_PATH`で保存先を上書きできる
- テストではインメモリSQLiteを使用する

## Notion連携

- CLI自身をMCPクライアントとして実装し、Notion APIを直接呼ばない
- Notion公式のHosted MCP `https://mcp.notion.com/mcp`へStreamable HTTPで接続する
- OAuth 2.0 Authorization Code + PKCEでユーザーが接続を許可する
- MCP SDKを使って接続し、利用可能なToolを実行時に取得する
- MVPでは親を指定せずPrivateページとして作成する
- 将来は保存先ページまたはデータベースをローカル設定で管理する
- OAuthトークンをSQLite、ログ、Gitへ保存せず、OSの安全な資格情報ストアを利用する
- アクセストークンの期限切れ時はリフレッシュし、再認証が必要なら明示する
- AIへ送る内容とNotionへ書く内容をプレビューで確認できるようにする
- MCP接続やTool実行のエラー時は元メモを保持し、再実行できるようにする
- 作成成功時はNotionページのURLを表示する

## 非ゴール

- Notion自体の置き換え
- MVPでのデスクトップGUI
- Web、モバイルアプリ
- 複数端末間の同期
- 複数ユーザーの共同編集
- 入力中のAI補完
- 初回からの複数LLMプロバイダー対応
- AIによる元メモの自動編集や削除
- ユーザーによる元メモの日常的な編集
- ベクトルデータベースを前提とした検索
- Gitプロジェクト情報の収集

## 非機能要件

- AIを使わないメモ保存はネットワーク通信なしで即時に完了する
- `ask`以外のコマンドではLLM APIを呼び出さない
- APIキー、OAuthトークン、PKCE verifierをログへ出さない
- 外部サービスの失敗で元メモを失わない
- シェルコマンド実行Toolをエージェントへ与えない
- LLM APIキーがなくても記録、一覧、表示、検索を利用できる

- [x] `list`で新しいメモから確認できる
- [x] `show`でメモをキー選択またはID指定できる
- [x] `search`で本文を部分一致検索できる

### AIエージェント

- [x] `memo ask "instruction"`で自然言語の依頼を渡せる
- [x] LLMが`listMemos`、`searchMemos`、`readMemo`を選択して実行できる
- [x] 複数回のTool呼び出し後に最終結果を返せる
- [x] 参照したメモIDを表示できる
- [x] 最大ステップ数でループを終了できる
- [x] Geminiが応答しない場合にリクエストをタイムアウトできる
- [x] 不正なTool引数と不正な最終出力を安全に処理できる

### Notion

- [x] AIがNotionページのタイトルと本文を提案できる
- [x] Notionへ送信する前にプレビューを表示できる
- [x] Hosted Notion MCPへOAuthで接続できる
- [x] 接続先ワークスペースと利用可能なToolを確認できる
- [x] 拒否した場合はNotionへ何も書き込まれない

## 開発フェーズ

### Phase 1：ローカル受信箱（完了）

- メモの入力とSQLite保存
- `list`、`show`、`search`
- 入力・保存・検索のテスト

### Phase 2：自然言語エージェント

- `memo ask`のCLI入口
- Gemini APIへの接続
- Tool定義とTool実行ループ
- 日付範囲による`listMemos`
- `searchMemos`と`readMemo`
- 構造化されたNotionページ案

### Phase 3：Notion MCP接続

- MCP SDKとStreamable HTTPクライアント
- OAuth 2.0 + PKCE認証
- OAuthトークンの安全な保存と更新
- Tool一覧の取得とワークスペース確認

### Phase 4：承認とページ作成（MVP完成）

- ページ案のプレビュー
- 対話的な承認
- `notion-create-pages`によるページ作成とURL表示
- エラー処理と統合テスト

### Phase 5：共通CoreとCLIの改善

- グローバルな`memo`コマンド化
- [x] 保存・取得・一覧・検索とAI Toolsのメモ読み取りを共通Coreへ分離
- [x] AI下書き生成・修正をモデル非依存のAgent Coreへ分離
- [x] 承認・修正・取消の状態遷移をUI非依存のCoreへ分離
- [x] 承認済み下書きのNotion書き込みユースケースを共通Coreへ分離
- [x] CLIと将来のデスクトップUIが共有するApplication APIを追加
- 日時表示のローカル化
- 設定コマンド
- 日次・週次テンプレート
- 必要性を検証した後の高度な全文検索

### Phase 6：デスクトップ入力UI

- 常駐デスクトップアプリ
- グローバルショートカット
- フォーカスを奪いすぎない小型入力ウィンドウ
- 保存成功後に自動で閉じる入力体験
- 共通Application APIを利用した下書きプレビューと承認
- CLIとデスクトップUIで同じSQLiteを安全に利用する

## 成功指標

- 思いついてから保存まで迷わず完了できる
- Notionを開くほどではないメモを実際に残すようになる
- 「今日一日分をまとめて」のような依頼だけで必要なメモが集まる
- Notionページ案を大きく書き直さずに承認できる
- AI機能がなくてもローカルメモとして利用できる
- ターミナル外で作業中でも、現在のアプリを離れず記録できる
- 訂正前後のメモから、思考の変化をAIが整理できる

## 未決事項

- Notionの保存先をページ配下とデータベースのどちらにするか
- Notionページ本文の既定テンプレート
- AIへ送信するメモ範囲を実行前に表示するか
- `memo ask`を対話入力でも利用できるようにするか
- 本文中の空行を将来どの操作で入力可能にするか
- デスクトップアプリの技術スタック
- グローバルショートカットの既定キーと変更方法
- 常駐方法、メニューバー表示、自動起動の範囲
- CLIとデスクトップアプリが同時に書き込む場合の排他制御
